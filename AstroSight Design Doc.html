AstroSight: UI/UX Design Document

Version: 1.0 (draft) | Companion to: PRD and Tech Stack docs Visual reference: the dark, editorial "science / space" concept you shared (used for style direction only; see section 2)

1. Design Vision

AstroSight should feel like a modern observatory journal: dark, calm, precise, and a little cinematic. The user is looking at real astronomical computation and a classical text, not a horoscope-magazine gimmick.

Design principles

  1. Show the evidence. Calculated facts, classical BPHS rules and AI synthesis each get a distinct visual treatment, so the user always knows which is which (this mirrors PRD requirement FR-6.4).
  2. Dark editorial calm. Near-black canvas, generous space, big confident type, hairline grid lines.
  3. One accent, used sparingly. A single warm accent marks the primary action or the single most important thing on screen.
  4. Imagery with purpose. Large cropped astronomical imagery sets the mood on entry screens; data screens stay clean.
  5. Traceable by default. Any rule-based sentence is one tap from its source (volume, chapter, printed page, PDF page, rule ID).
  6. Honest framing. The product never claims astrology is scientifically proven (see section 12).

3. Brand Identity

  • Name: AstroSight
  • Tagline options: "Read the sky." / "Computed. Cited. Interpreted." / "Classical wisdom, calculated."
  • Logo idea: a thin ring (orbit) with a small dot and a horizontal line through it (horizon or "sight" line). Monoline, works at 24px.
  • Tone of voice: calm, precise, respectful. Explains what was calculated before what it might mean. Avoids fate-declaring phrases ("you will…"); prefers "classical texts associate this with…".

5. Typography

Display / headlines Inter Tight or Space Grotesk 600, tight tracking, sizes 56–120px on hero

Classical quotes (BPHS text) Source Serif 4 or Newsreader Italic or regular, so quoted scripture reads differently from UI text
Metadata / labels Inter, uppercase 11px, +8% letter-spacing, --text-3
Numerics (degrees, dates) JetBrains Mono or Inter tabular For longitudes like 123°27′, Julian Day

Typography carries the three-layer idea: sans = facts and UI, serif = classical rule, sans in a tinted panel = AI synthesis.

6. Layout and Grid

  • Desktop: 12-column grid, 1440 base, 24px gutters. Left rail 72px, content area with hairline column dividers like the reference.
  • Tablet: 8 columns; rail collapses to icons.
  • Mobile: 4 columns; rail becomes a bottom tab bar (Chart, Ask, Explore, Palm).
  • Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 72.
  • Radius: 12px cards, 999px for round CTA and chips. Borders 1px --line.
  • Texture: subtle dot grid or grain at 3–5% opacity on --bg-0. Never behind body text.

8. Key Screens

8.1 Landing (reference: "Learn by Exploring")

  • Full-bleed dark hero, giant headline split around a cropped planet or moon: "Read the sky."
  • Small ghost tagline top-left. A one-line description top-right, e.g. "Swiss Ephemeris precision. Classical BPHS rules. Cited interpretation."
  • One round accent CTA bottom-left: Cast my chart ↓.
  • Below the fold: three-step strip (Calculate → Retrieve → Interpret) and a "How it works" link.

8.2 Birth Input ("Cast Chart")

  • Split layout: left = large title "Your moment of birth."; right = form.
  • Fields: date, time (with "unknown time" warning), place (autocomplete), resolved lat/long and timezone shown read-only with an edit link, settings drawer (ayanamsha, house system, defaults shown).
  • Live "Resolved to UTC" line so the local-to-UTC step is visible and verifiable.
  • Primary round CTA: Cast chart.

8.3 Chart Dashboard (reference: Articles grid + Expeditions map)

  • Center: chart visual. Toggle South Indian / North Indian / Wheel. Planet dots with abbreviations, retrograde marked with R, dignity shown as a small superscript.
  • Right column ("From the calculation"): Lagna, Moon sign, nakshatra + pada, current Mahadasha/Antardasha.
  • Below: planets table in mono numerals (sign, degree, nakshatra, house, speed, R).
  • Tabs: Chart · Houses · Dashas · Yogas · Ask.
  • Footer strip: Julian Day, ayanamsha, house system, ephemeris mode, so the reader can audit the setup.

8.4 Interpretation / Ask (reference: article detail, title left / text right)

  • Left: the question or house/planet in large type (e.g. "Mars in the 10th house.").
  • Right: the answer in three visually separated layers:
    • A. Calculated fact (blue rule, sans): "Mars is in the 10th house in Aries, 14°."
    • B. Classical rule (gold rule, serif): the BPHS passage, verbatim, with a source chip Vol I · Ch 23 · p. 261.
    • C. Synthesis (violet-tinted panel): the AI's readable interpretation, labelled "AI synthesis".
  • Each B block has a "View source" action opening the Source Drawer (8.5).
  • Query chips above: Career, Marriage, Wealth, Education, Dasha.

8.5 Source Drawer

Right-side drawer showing: rule text (source_text), surrounding context_text, book, volume, translator, chapter and title, printed page and PDF page (separate), rule ID, extraction status badge (Verified in green or Needs review in orange).

8.6 Dasha Timeline

Horizontal timeline of Mahadashas with the current period highlighted in accent; click expands Antardashas. Related BPHS dasha rules appear as cards below.

8.7 Knowledge Explorer (reference: Articles / Series grid)

  • Tabs: Houses · Planets · Signs · Yogas · Dashas · Ashtakavarga · All.
  • Card grid: rule headline, tiny uppercase meta (CH 14 · P 194), priority dot, verified/needs-review badge.
  • Filters: house (1–12), planet, topic, priority, status. Search box for semantic queries.
  • Purpose: lets an evaluator browse the knowledge base and verify extraction quality.

8.8 Palm Reading (separate module)

  • Distinct entry point; visually flagged with a different tint (e.g. warm terracotta accent) so users understand it is a different pipeline, not part of the chart.
  • Steps: upload / camera → guidance overlay (hand outline, good-light tips) → validation result → processing → results.
  • Results: the photo with detected lines overlaid (toggle each line), extracted features list, then interpretation text.
  • Error states: no hand detected, blurry, too dark, wrong orientation, each with a clear retry hint.

8.9 Methodology / About

Explains the pipeline, sources (BPHS Vol I & II, translator), sidereal Lahiri default, limitations, and the disclaimer. Doubles as academic documentation for evaluators.

8.10 Review Queue (developer/admin, optional)

Table of needs_review rules and problem pages, with source text side by side and an "approve / edit / reject" action. Not part of the public UI.

10. Interaction and Motion

  • Page transitions: 200–300ms fade/slide; no bouncy animations.
  • Hero: very slow parallax on the planet image; respects prefers-reduced-motion.
  • Chart: planets fade in sequentially on first render (skip when reduced motion is on).
  • Loading: skeleton blocks plus a staged status ("Resolving timezone → Calculating positions → Retrieving rules → Writing interpretation"), which reinforces the pipeline.
  • Hover: cards lift by 2px and border brightens; focus rings always visible in --accent.

11. States and Edge Cases

State Design response
Birth time unknown Inline warning; hide or grey Lagna-dependent features; explain why.
Place not found Suggest alternatives; allow manual lat/long.
No rules retrieved Say so plainly; show only calculated facts. Never fill gaps with unsupported text.
Rule needs_review Orange badge on the rule; note that the text is under verification.
LLM/API failure Show the chart and retrieved rules without synthesis, with a retry button.
Palm image invalid Specific reason plus retry tips.
Empty Knowledge Explorer filter "No rules match" with a clear-filters action.

12. Content and Ethics

  • Persistent, non-intrusive disclaimer: "AstroSight is an academic implementation of computational Vedic astrology and AI-assisted interpretation. It does not claim scientific validity of astrological predictions."
  • Prefer attribution language: "According to BPHS (Vol I, Ch 23)…".
  • No fear-based or medical/financial/legal directives; add a gentle note on sensitive topics such as health and longevity.
  • Privacy: explain what birth data is stored and offer delete-my-data (define retention before deployment).
  • Copyright: display only short rule excerpts with provenance; no full-book reading view of the translation.

13. Accessibility

  • WCAG AA contrast for all real text; ghost taglines are decorative and marked aria-hidden.
  • Full keyboard navigation; visible focus states.
  • Never use color alone: layers also carry text labels ("Calculated", "Classical rule", "AI synthesis"); status badges include text.
  • Chart has a text/table alternative listing every planet's position.
  • Respect prefers-reduced-motion; minimum touch target 44px.
  • Minimum body text 15px; avoid the tiny metadata sizes for anything essential.

15. Imagery and Assets

  • Hero and section imagery: public-domain astronomy (e.g. NASA) or your own renders; keep a credits list.
  • Icons: a single monoline set (e.g. Lucide) at 1.5px stroke.
  • Planet and sign glyphs: Unicode astrological symbols or a custom SVG set for consistency.
  • Textures: generate a dot-grid/grain PNG or CSS pattern; keep files small.

16. Implementation Notes

  • Framework: for this look (rail layout, layered blocks, drawers, animated chart) I'd move the frontend to Next.js + Tailwind rather than Streamlit. This refines the 💡 frontend suggestion in the Tech Stack doc; Streamlit is still fine for a quick demo without this styling.
  • Map the section 4 tokens into tailwind.config and CSS variables; build the chart as a React SVG component.
  • Backend endpoints stay as in the tech stack: /chart, /interpret, /palm, plus /rules for the Explorer and Source Drawer.
  • Keep the palm module in its own route and codebase folder to preserve the pipeline separation.
